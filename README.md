# Проект распознавания мультиязычных текстов OCR

## Описание проекта

Данный проект является сервисом для оцифровки текстовых документов по фотографии. Для работы сервиса использованы технологии `Pytorch Lightning` + `Hydra`, а в качестве моделей вариации детектор + рекогнайзер. Подробнее о моделях можно узнать в коде ядра и моделинга.
В качестве интерфейса взаимодействия предусмотрено API с сайтом на основе `Python FastAPI` + `JS React` или развёртывание на локальной машине.

## Входные данные

На вход системы в случаях работы с API и локальным запуском подаются изображения в форматах `.jpeg, .jpg, .png` или документы формата `.pdf`

![alt text](core/assets/examples/example_predict.png)


## Выход модели

Выходом модели является изображение с локализацией текста и предсказаниями в отдельных bounding boxes. Также для проверки качества модели и отладки возвращаются и конфиденсы для детекции и распознавания отдельно.

## Установка окружения

Во всём репозитории используется единая среда на основе менеджера пакетов `poetry`.
Для установки окружения рекомендуем использовать `anaconda`.
Версии пакетов и python зафиксированы, универсальный способ установки:

```
conda create -n ocr-project python=3.10.16
conda activate ocr-project

pip install poetry==2.2.1
poetry install
```

При невозможности установить `torch` из оф. источников он подтянется в версии `cpu` с другого места.

Подробнее про зависимости модуля можно прочитать в файлах `pyproject.toml` и `poetry.lock`

## Запуск сервиса

Для работы с полностью готовым сервисом потребуется запустить `core` и `service` части.

### 1. Запуск ядра


#### 1.1. Скачивание весов
Перед началом запуска надо подтянуть веса:

```
dvc get https://huggingface.co/NerfmanOriginal/ocr-diploma-models parseq_baseline__2026_02_11.pth -o /weights/
```

Список актуальных весов, скачиваемых через huggingface:
| Название модели | Актуальные веса |
|-|-|
| **parseq_base** |`parseq_baseline__2026_02_11.pth` |
| **crnn_vgg16_lstm256** | `crnn_vgg16_lstm256_baseline__2025_10_08.pth`|

#### 1.2. Запуск локального прогона

Теперь переходим в папку `/core`.

Там инструкции и подробный пайплайн по запуску. 

Есть варианты с API или локальным запуском. Если выбрали API, необходим следующий шаг.

### 2. Запуск сервиса (если в ядре выбран API)

Существует два варианта для запуска сервиса с поднятым локальным сайтом.

#### 2.1. Вариант с start.bat

Работает на windows.
Подробные инструкци по установке окружения в npm прописаны в папке `/service`.

После этого запускаем 
```
start.bat
```

После запуска можно пользоваться приложением.

#### 2.2. Вариант с отдельным запуском и отладкой

Если нет возможности запустить оба сервиса или нужен только один из них, запуск проводить из папок сервиса и ядра, подробные инструкции в `/service` и `/core`.

## Работа с pre-commit и линтеры

В качестве основных средств для поддержания качества кода мы используем `flake8`, `isort`, `black`. Все их параметры прописаны в `setup.cfg`.

Для запуска прекоммита

```
pre-commit install
```

Дальше делаем просто

```
pre-commit run # можно добавить флаг --all-files для проверки всего проекта
```
